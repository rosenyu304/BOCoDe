# AGENTS.md — working with BOCoDe

BOCoDe is a PyTorch-native benchmark library: 300+ black-box optimization
problems (engineering, HPO, synthetic) behind one `evaluate()` API, plus
reference BO/EA baselines in `algorithms/`.

## The two rules you must not get wrong

1. **Everything is MAXIMIZATION.** `evaluate()` returns objectives to maximize.
   If your optimizer minimizes, negate the objective.
2. **Constraints are inequality constraints, feasible when `gx <= 0`.**

## Install & test

```bash
pip install bocode                # core (most problems)
pip install "bocode[mujoco,hpo]"  # per-problem-group extras (see pyproject.toml)
pytest tests/                     # smoke tests skip problems whose extra is absent
```

Some problems fetch large data on first use (from the HF dataset
`rosenyu/bocode-data`); network needed once, cached in `~/.cache/bocode`.

## Core API (everything an agent needs)

```python
import bocode

bocode.list_problems()                         # all registered problem names
bocode.list_problems(application="Engineering", constrained=True)
bocode.list_synthetic()                        # synthetic test functions
                                               # (separate from list_problems)
meta = bocode.get_metadata("Car")              # registry problems only: dim,
                                               # objectives, constraints, source
problem = bocode.get_problem("Car")()          # instantiate by name
x = problem.sample(5, seed=0)                  # (5, dim) tensor of valid points
obj, cons = problem.evaluate(x)                # maximization; cons feasible <= 0
```

- `x` is a `torch.Tensor` of shape `(batch, dim)` inside `problem.bounds`.
- Use `torch.float64` for anything GP-based.
- Per-problem JSON metadata lives in `bocode/opt_problems_metadata/` — filter
  problems programmatically instead of hard-coding names.
- Mixed-variable problems: integer/categorical dims are listed in metadata
  (`variable_types`); `sample()` already respects them.

## Running a reference baseline

```bash
python -m algorithms.single_obj.gp_ucb --problem Car --init 10 --iters 40
```

`algorithms/` is organized by optimization class (`single_obj`,
`single_obj_constrained`, `multi_obj`, `multi_obj_constrained`); each file is a
single-file, CleanRL-style implementation with a common CLI
(`--problem --iters --seed --device`). See `algorithms/README.md`.

## Repo layout

- `bocode/` — the installable package (problems, registry, metadata, fetch)
- `algorithms/` — reference optimizers (research code, not part of the wheel)
- `examples/` — runnable examples incl. a batch runner and SLURM-array template
- `tests/` — pytest smoke tests
- `docs/` — Sphinx sources for https://bocode.readthedocs.io

## Gotchas

- Problem classes may need optional extras; missing ones raise an actionable
  ImportError naming the extra to install. Do not add hard dependencies.
- `LassoLeukemia` is 7129-dimensional; `AntPolicy` is 840-dimensional — check
  `get_metadata(name)["dim"]` before launching expensive methods.
- The registry (`bocode/_registry_data.json`) is generated by
  `tools/generate_registry.py`, and metadata by `tools/generate_metadata.py` —
  regenerate BOTH when adding a problem, and never hand-edit generated files.
- Keep new problems cited: docstring + `source` field in metadata.
